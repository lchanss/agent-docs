# agent-docs

AI 코딩 에이전트(Claude Code)와 함께 개발할 때 쓰는 프론트엔드 개발 기준과 코드 리뷰 스킬입니다.
에이전트가 짠 코드에도 사람이 짠 코드와 같은 기준이 적용되도록 만드는 것이 목적입니다.

## 구성

| 경로 | 내용 |
|---|---|
| `frontend-guidelines.md` | 코드 작성 기준. [Frontend Fundamentals](https://frontend-fundamentals.com/code-quality/)의 4가지 원칙(가독성·예측 가능성·응집도·결합도)을 바탕으로 보완 |
| `CLAUDE.md` | 위 가이드를 에이전트가 항상 참고하도록 연결 |
| `skills/frontend-code-review/` | React/TypeScript 코드 리뷰 스킬 |

## frontend-code-review

AI 리뷰는 그럴듯하지만 근거 없는 지적이 많아 오히려 안 읽히기 쉽습니다.
이 스킬은 **확인된 문제만 보고하는 리뷰**를 목표로 설계했습니다.

**원칙**
- 구체적인 실패 시나리오를 댈 수 없는 지적은 보고하지 않습니다. 지적 0건도 정상 결과입니다.
- 모든 제안에는 무엇이 좋아지고 무엇이 나빠지는지 트레이드오프를 함께 적습니다.
- 레포에서 일관되게 쓰는 패턴은 실수가 아니라 결정으로 봅니다.
- 승인이나 변경 요청은 하지 않습니다. 머지 판단은 사람이 합니다.

**동작 방식**
1. 변경된 파일 전체와 CLAUDE.md, package.json, lint 설정을 먼저 읽어 맥락을 파악합니다.
2. 정확성·보안 / 가독성·예측 가능성 / 응집도·결합도 / 접근성·UX 상태 / 성능, 5개 관점의 서브에이전트가 병렬로 후보를 냅니다. (관점당 최대 3개)
3. 각 후보를 실제 코드에서 다시 따라가 보고, 재현되지 않거나 레포 관례·CLAUDE.md가 허용하는 것은 버립니다.
4. 남은 것만 CONFIRMED / PLAUSIBLE로 표시해 보고하고, 버린 건수와 이유도 함께 남깁니다.

작은 변경(3파일 또는 150줄 이하)은 서브에이전트 없이 직접 리뷰해 비용을 줄입니다.

**모드**
- diff 모드: PR 번호나 브랜치 변경분을 리뷰합니다.
- audit 모드: 경로를 지정해 기존 코드를 점검합니다.

**프로젝트별 확장**
레포에 `.claude/review-notes.md`를 두면 그 프로젝트의 불변 조건과 의도된 패턴이 일반 체크리스트보다 우선합니다.
템플릿은 `skills/frontend-code-review/assets/review-notes-template.md`에 있습니다.
